# Currency choice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Per the project CLAUDE.md, this plan lists files, behaviour and tests — no full code.

**Goal:** Let each household pick its display currency (9 choices, with flags) at onboarding and in Settings, without converting any amount.

**Architecture:** Amounts stay integer thousandths (`Mil`). A currency table (`src/shared/currencies.ts`) drives formatting, parsing and decimals; a module signal holds the current currency, fed by the profile. `profiles.currency` is stored server-side; `set_currency` and `couple_join` keep a household on one currency.

**Tech Stack:** Vite + Preact + TypeScript, `@preact/signals`, Supabase (Postgres + RLS), Vitest + PGlite, Playwright.

**Spec:** `docs/superpowers/specs/2026-09-27-currency-design.md` (read it first).

## Global Constraints

- Work in the worktree `../stouchi-devise`, branch `feat/devise`. Ships after the 1 November launch; not part of Session C.
- Money: integer millimes, never floats; helpers in `src/shared/money.ts`.
- UI text French only, in `src/shared/i18n/fr.json`; no hard-coded strings in components.
- Codes: exactly `TND EUR USD GBP CAD CHF MAD DZD LYD`; default `TND`. TND and LYD have 3 decimals, the rest 2.
- Display format: French number format, suffix after a no-break space (`1 200,50 €`).
- No conversion, ever: switching currency keeps every stored amount.
- Touch targets ≥ 44 px (picker rows ≥ 56 px); reduced motion respected (spec §5.5–5.6).
- First-load JS ≤ 150 kB gzip (`npm run build && npm run check:size`).
- Migrations are additive; nothing runs on production Supabase without explicit approval.
- `npm run check` before every commit; commit messages in French, in the history's style; commit only when the owner asks.

## Review Focus

1. **Old 3-decimal amounts after switching to a 2-decimal currency** (12,345 TND → EUR): display rounds half-up to cents (`12,35 €`), the stored value stays 12345 until the person edits it; totals are summed on `Mil` then rounded once, never rounded per line. Test in Task 1.
2. **Unknown currency code from the server** (a future code, or a corrupt mirror row): the app falls back to TND and does not crash. Test in Task 3.
3. **Onboarding draft saved before this release** (step index stored locally): inserting `currency` at index 1 must not send someone mid-way back or skip a step — resume by step name. Test in Task 5.
4. **Partner changes the currency while I'm offline or the app is open:** my profile row updates on the next sync / realtime event and every figure re-renders in the new unit without a reload. Test in Task 3.
5. **Aam Salah proposes `12,345` in EUR:** rejected by validation with the normal "can't store that amount" path, never saved rounded. Test in Task 7.
